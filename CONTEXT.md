# Context

The words surfcult's code and documentation use, and the code item each one names.

## Channels and media

- **Channel**: a numbered entry in `channels.toml`, `config::Channel`. It has a name, a plan (`config::Plan`: one source in one mode, or time-of-day blocks) and optional grid, break, filler and sign-off settings. `Plan::sources` lists the sources the caller resolves into program pools.
- **Source**: where a channel's items come from in Jellyfin: a library, collection, tag, genre or series, `config::Source`.
- **Media source**: the interface that lists and resolves media items without saying where they come from, `library::MediaSource`. Its two adapters are the library cache in the `Store` and `library::FakeMediaSource` for tests.
- **Library cache**: the `library_*` tables in the store, a copy of the Jellyfin library. Everything except the sync step reads the library from here, so it keeps working while Jellyfin is down.
- **Sync**: `jellyfin::sync`, which fetches the library from Jellyfin and replaces the library cache in one transaction. The caller passes the sync time; a failed sync leaves the cache as it was. `SyncWorker::apply` does not rewrite a snapshot that matches the one it last wrote (`SyncReport::written` is false) and only records the sync time.
- **Sync worker**: `jellyfin::SyncWorker`, which fetches the library on its own thread at a fixed interval and sends each result back. The store's owner writes the newest snapshot with `SyncWorker::apply`; the worker never touches the store.
- **Device profile**: what the Pi plays directly and what Jellyfin transcodes to, ADR 0001 decisions 3 and 4. Its rules are the constants in `library::profile`; `needs_transcode` and the `DeviceProfile` that `JellyfinClient::playback` sends are both built from them.
- **Playback**: how the player gets an item, `jellyfin::Playback`, from `JellyfinClient::playback`. `Direct` is the file as stored, and the player seeks to the start position; `Transcode` is a progressive MPEG-TS stream that already starts there. Neither URL carries the key, and playback is never reported to Jellyfin.
- **Transcode session**: the device id and play session id of a transcode surfcult started, `jellyfin::TranscodeSession`. `JellyfinClient::stop_transcode` stops it when playback ends.
- **Program pool**: the ordered items a channel, block or default draws its programs from, built from its source by `library::resolve_pool(channel, source, media)`; `schedule::extend` takes one per source. A collection keeps its member order and expands each series in it to its episodes; a library, tag or genre keeps the cache's order with each series' episodes gathered together; a series gives its episodes. A source that matches nothing is a `PoolError` naming the channel and the source, never the whole library.
- **Episode order**: season, then episode number, `library::SeriesEpisode`. Season 0 (specials) comes first, missing numbers come last, and ties keep the cache's order.
- **Music video**: a Jellyfin `MusicVideo` item, `library::MediaKind::MusicVideo`, cached with its artists and album (`MediaItem::artists`, `MediaItem::album`) and played like a movie. Its display title is `Artist – Title` (`MediaItem::display_title`).
- **Song**: a Jellyfin `Audio` item from a library of type `music`, `library::MediaKind::Song`, cached with its artists, album and album id (`MediaItem::album_id`, whose primary image is the cover). It has no video streams. Its display title is `Artist – Title`.
- **Music channel** and **picture**: a channel with a `picture` key (`config::Picture`: `cover` or `visualizer`), which plays songs and nothing else. `Channel::plays` gives `library::Plays::Songs` for it and `Plays::Videos` for every other channel; `resolve_pool` takes it, so a video channel never gets a song through a genre the two share.
- **Series member**: a collection member that is a series id rather than an item id, `library::Collection::members`. It stands for all of the series' cached episodes.

## Clips

- **Clip**: a short local video file and its probed duration, `clips::Clip`: an ad, ident, bumper, tune-in clip, filler or slate.
- **Clip pool**: a named directory of clips on the Pi, `clips::Pool`, scanned by `clips::ClipLibrary`. It is not a program pool.
- **Tune-in clip**: the clip the `tuner` plays between static and the program when the viewer changes channel. It is picked from the tune-in clip pool to cover the program's expected start-up time.

## Schedule

- **Event**: one scheduled stretch of one media item, a half-open interval `[start_ms, end_ms)`, `timeline::Event`. At a boundary the later event is the one on.
- **Program**, **break**, **filler** and **ident**: the four `timeline::EventKind`s. A program is an item from the program pool. A break event is one whole clip from a pool of kind `commercial` or `trailer`; filler pads a break the break clips do not fill, plays the time a blocks channel has no block or default for, and later fills a gap up to the next grid slot; an ident is a short station identification, bump, stinger or slate, from a pool of kind `bump`, `stinger` or `ident`; ident events also pad a break from its pad pool and play the sign-off. Idents show no watermark.
- **Commercial break**: the break events and the pad at one cut in a program, `breaks.length` long, filled by `schedule`: one clip from the `open` pool, clips drawn from the weighted break pools (`breaks.pools`, or `breaks.pool` for one), the pad, then one clip from the `close` pool. Breaks add to the slot.
- **Pool kind**: what an interstitial pool's clips are, its `kind` key (`config::ClipKind`): `commercial`, `trailer`, `bump`, `stinger`, `ident` or `filler`. It sets the event kind they are scheduled as. Without the key a pool a channel's breaks draw from is `commercial` and any other is `filler`.
- **Between**: a channel's `between` key (`config::Between`): one clip, or a `length` filled like a break, played where a program ends and the next program of the same block or stretch starts. Not before a block's first program, nor across a sign-off.
- **Cut point**: where a program is cut for a break: a multiple of `breaks.every` in the program's time, moved to a chapter mark within 60 seconds when there is one. The program's events then have increasing `media_offset_ms`.
- **Break pool rotation**: the order a pool's clips are drawn in by breaks and `between`, its `rotation` key (`config::Rotation`). Each pool has one rotation per channel, shared by all its uses. With `order` (the default) clips play in pool order, continuing after the pool's newest clip the channel aired if it started within the last 24 hours, else from the first clip. With `shuffle` each break draws its own order, seeded from the channel and the time the walk starts. Either way a clip plays at most once per break, and clips that share a media id count once.
- **Repeat limit**: a pool's optional `repeat_after` duration, for pools breaks and `between` draw from. On one channel, a clip from the pool does not play again until that long after its last airing started; a break no clip can fill is padded instead. Every clip the channel airs counts, whatever placed it. `extend` reads the stored clip events (`Store::clips_between`) back to the longer of 24 hours and the longest limit.
- **Pad pool**: the `breaks.pad` pool, idents and slates that pad a break's shortfall as one `Ident` event. When it has no clip, the channel's filler pool pads instead, as a `Filler` event.
- **Clip id**: the `media_id` of a break or filler event, the clip's canonical path as text (`schedule::clip_media_id`).
- **Channel schedule**: a channel's stored events. `schedule::extend` keeps it filled to the horizon and `Store::events_between` reads it.
- **Horizon**: how far ahead of now a schedule is kept filled, seven days (`schedule::HORIZON_MS`).
- **Extend**: one `schedule::extend` call. It starts at the later of now and the end of the last stored event, generates up to the horizon, and writes the new events in one transaction.
- **Regenerate**, **freeze point** and **boundary**: `schedule::regenerate` replaces a channel's schedule after a config or runtime change. The freeze point is now plus 30 minutes (`schedule::FREEZE_MS`); the boundary is the first place at or after it where the generator can resume exactly: a program's start, uncovered filler or the gap before a sign-off, the sign-off clip, or time with no events. Events before the boundary are kept as they are, and the new events from it on resume from the history before it.
- **Mismatch** and **fit**: a program event whose file is shorter or longer than the event expects. `schedule::fit` returns what plays in the event's time: a short file padded from the filler pool to the event's end, a long one cut there. A difference of up to 500 ms (`schedule::FIT_TOLERANCE_MS`) is no mismatch. `schedule::record_fit` records it in playback history as `padded`, `short` (nothing to pad with) or `cut`.
- **Trusted clock**: the caller's statement, through the `clock_trusted` argument, that the system clock is synchronized. `extend` does nothing without it, so a Pi with a wrong clock never stores a wrong week. The run loop decides with `run::clock_trusted`: `SURFCULT_CLOCK_TRUSTED`, then systemd's `NTPSynchronized`, then `/run/systemd/timesync/synchronized`.
- **Sequential**: a mode, `config::Mode::Sequential`. Items play in program pool order, continuing after the resume point and wrapping from the last item to the first.
- **Shuffle** and **cooldown**: in shuffle mode (`config::Mode::Shuffle`) each program slot picks at random, seeded from the channel and the slot's start, from the items not cooling down. With N playable items and k = max(1, ceil(N / 4)), the N - k most recently played distinct items are cooling down.
- **Resume point** (cursor): the media id of the channel's last stored program event, which says where the next extend continues. It has no table of its own; `extend` derives it from the events, so it cannot disagree with them.
- **Weighted** and **source weight**: in weighted mode (`config::Mode::Weighted`) a lineup has several sources, each with a weight, a whole number of at least 1 (`config::WeightedSource`, written `{ jellyfin_series = "Name", weight = 3 }` in `sources`). Each program slot first picks a source with probability proportional to its weight, seeded like the shuffle, then picks an item from that source's pool by the shuffle's cooldown, counted per source pool. A source with nothing playable is skipped and reported with `Note::SourceNotPlayable`.
- **Block**: a time-of-day window on some days of the week with its own source (or weighted sources) and mode, `config::Block`, in a channel with `mode = "blocks"`. Its times are local wall-clock times in the config's time zone, so its length in real time changes on the days the clocks change.
- **Default**: the lineup (`config::Lineup`: sources, mode) a blocks channel plays when no block is on. Without one the channel's filler pool plays, and without that the time is dead air. The tuner does not play a long filler stretch; it shows the stand-by card with `Reason::NoProgramSoon`, and the playback driver then plays the filler.
- **Lane**: the program pools of one lineup in one mode inside the generator, `schedule::Lane`: a block, the default or a whole channel. A weighted lane has one `SourcePool` (source, weight, items) per source; any other mode has one. Each lane keeps its own place.
- **Span**: a stretch of a blocks channel's time in epoch milliseconds, covered by one block or by none, `Span` in `src/schedule/blocks.rs`, from `spans`. A program on at a span's end is cut there.
- **Dead air**: time a channel has nothing to play and no filler clip: a blocks channel's time with no block or default, or the gap before a sign-off. It has no events and is reported as `Note::DeadAir`.
- **Sign-off**: a channel's `sign_off` (`config::SignOff`): the clip that ends each night, one `Ident` event that starts at `at`, local time in the config's time zone. It is the named file in the sign-off pool, else the pool's first clip; with no usable clip there is none and `Note::NoSignOffClip` says so. No program or break starts that would still be on at `at`. The gap between the last program and the sign-off is filled from the channel's filler pool, its last clip ending as the sign-off starts, or is dead air without one.
- **Off the air**: the time from the end of the sign-off clip to `until`, the next morning when `until` is not after `at`. The channel has no events then. A night (`Night` in `src/schedule/sign_off.rs`) is the epoch span from `at` to `until`, read with the same clock-change rules as a block. It overrides blocks and the default. At `until` the channel's plan resumes where it left off.
- **Recent history**: the media ids of the channel's most recent stored program events before the new window, newest first, read with `Store::recent_programs_before` and passed as `Resume::recent`. Shuffle, weighted and blocks channels read more than one row, to find the items cooling down (in each source's pool, for a weighted lineup) and each block's place; a sequential channel reads just its last program (`Store::last_program_before`). It is not the `playback_history` table, which records what the tuner started.

## Guide

- **Guide cell**: one program in the program guide, `guide::Cell`, with its start, end, title and an empty description (the media model has none). A program cut by breaks is one cell from its first segment's start to its last segment's end; breaks, filler and idents are not cells.
- **Guide window**: the stretch of time the guide shows, `guide::Window`, by default now through three hours (`guide::DEFAULT_SPAN_MS`). Cells that overlap it are kept whole, not clipped.
- **Progress**: how far through the current cell a moment is, `guide::Cell::progress`, counting breaks inside the program as program time.

## Running

- **Store**: the one SQLite file, `store::Store`. It holds the channel schedules, the playback history and the library cache. The composition root owns it and passes it to each call (`&mut` to write, `&` to read); nothing else keeps a store between calls, except the read API, which opens its own read-only connection (`Store::open_read_only`, no create, no migration) to the same file.
- **Composition root**: the code that creates the store, the player and the tuner and drives them on the Pi: `run::app::run`, behind `surfcult run`. Its loop is `run::Tv`. See `docs/reference/run.md`.
- **Run loop**: `run::Tv::step`, one pass of the TV every 20 ms on the thread that owns the store: keys, player events and the tuner, the driver, the banner and schedule upkeep.
- **Playback driver**: the part of the run loop that keeps the screen on the tuned channel's schedule after the tuner's sequence (`src/run/driver.rs`). At each event boundary it plays the program at its live position, plays the event's clip, or shows the stand-by card. It queues the next item behind a clip that ends at its event's end, and replaces a program at its boundary.
- **Input device**: a Linux input device the run loop reads keys from (`input::EvdevInput`): the Pi's CEC remote, found by a name containing `vc4-hdmi`, and every keyboard. `input::Key` is what a press asks for: next or previous channel, the banner, or quit.
- **Banner**: the channel number and name, the program on now and its local start and end, the program after it, shown for 5 seconds after a channel change and on OK, `overlay::Banner`. `MpvPlayer` draws it in the Cable Grid design (`paint::banner`) in overlay layer 63; any command that replaces the screen removes it.
- **Tune-in pool**: the clip pool the tuner's tune-in clips come from, the top-level `tune_in_pool` key, `tune-in` by default.
- **Player**: the screen as the tuner sees it, `player::Player`: static, the stand-by card, a clip, a queued program, seek, stop and overlays. `player::MpvPlayer` drives a real MPV over its JSON IPC socket; `player::FakePlayer` records commands for tests.
- **Stream resolver**: what turns a program's media id and start position into a URL, its HTTP headers and the media position the stream begins at, `player::mpv::StreamResolver`. It keeps Jellyfin out of the player.
- **Static**: grey noise generated live by FFmpeg's `lavfi`, `player::mpv::STATIC_SOURCE`. The tuner shows it for the half second after a key press, and leaves it up when a tune fails because there is no tune-in clip, the schedule cannot be read or the player failed.
- **Stand-by card**: colour bars with PLEASE STANDBY on a black band across the middle, matched to the owner's design, `Player::show_standby`. The tuner shows it when a channel has nothing to play: no events, a gap, a long filler stretch, or a program the media source cannot look up. MPV generates the bars live at 640x360 and 30 frames a second (`player::mpv::STANDBY_SOURCE`), scales them up and draws the band and text from an ASS subtitle file blended into the picture, so the card's display filters cover them too. The default text is drawn from vector outlines derived from Oswald (`tools/standby/`); any other `standby_text` is set in DejaVu Sans Bold.
- **Display filter**: a named effect on the picture, `player::Filter`, set in the `[display]` table of `channels.toml` (`config::Display`). `filters` are on everything on screen; `standby_filters` (by default `crt` and `glitch`) are added while the stand-by card shows. The card's filters are the global ones followed by its own, each once (`player::standby_filters`).
- **CRT shader**: the `crt` display filter, the GLSL user shader `assets/shaders/crt.glsl` (`player::mpv::CRT_SHADER`): scanlines, slight curvature with a vignette, red and cyan fringing toward the edges, a faint flicker and a rolling band. MPV applies it through its `glsl-shaders` property. It is tuned to keep the picture about as bright as without it. Blended subtitles, including the card's band and text, go through it; MPV's OSD is drawn after it.
- **Glitch**: the `glitch` display filter. At random moments, on average every `glitch_every` (20 s), one or two thin slices of the stand-by card's band shift a few pixels sideways and its red and cyan text move a few pixels further apart for 80 to 150 ms. `MpvPlayer` steps it in `poll_event` and shows the flicker as a second subtitle track over the card's; it does nothing while the card is not up.
- **Overlay**: a premultiplied BGRA bitmap drawn over the video in one of 64 layers, `player::Overlay`.
- **Canvas**: a bitmap the TV's interface is drawn into in the Cable Grid design, `paint::Canvas`; `to_overlay` turns it into an overlay.
- **Guide screen**: the program guide on the TV, opened with the guide key, `run::guide::Guide` for the focus and the rows on screen and `paint::guide` for the drawing. The video moves into the top-right quarter (`player::VideoArea::TopRight`) while it is open. Not the `guide` module, which builds the cells it shows.
- **Web admin**: the page served at `/`, in the Cable Grid design, `assets/web/` and `server::web`. `surfcult run` serves it with control of the TV (`server::Control`: `AdminCommand`s down a channel to `Tv::admin`, `TvStatus` back); `surfcult serve` serves it read only. Inside `run` it also edits a channel's settings in `channels.toml` (`config::edit`, `server::edit`) and hands the TV the new config (`AdminCommand::Reconfigure`).
- **Picture menu**: the TV's settings menu, opened with the menu key, `run::menu` and `paint::menu`. It holds the CRT filter; OK steps it to the next level.
- **Viewer setting**: a choice the viewer made on the TV, stored by name in the store's `viewer_settings` table (`Store::viewer_setting`), such as `crt`. It wins over the environment's default.
- **Watermark**: the SCTV station bug in the top-right corner, `paint::watermark`, in overlay layer 8 at 60% opacity. The beside form shows for 3 seconds after a channel change settles and then fades over 1 second; the under form shows through break and filler events. `run::watermark::Watermark` decides which and how opaque.
- **CRT pass**: scanlines, glow and a colour fringe baked into an interface overlay before it is shown, `paint::crt::apply`, at the viewer's `paint::Crt` level (Heavy, Light or Off). It never touches the video, and it is separate from the CRT shader.
- **Watchdog**: the part of `MpvPlayer::poll_event` that notices a dead or hung MPV (a hung one fails a `get_property pid` check sent at most every few seconds), starts a new one and reports `PlayerEvent::Restarted`. The tuner then tunes the current channel again.
- **Look-ahead**: the tuner looks up the schedule at the moment the tune-in clip will end, not at the key press, with `timeline::program_from`, so the program is queued at the right offset. If a break is on then, it gets the program after the break at that event's `media_offset_ms`.
- **Live position**: where the schedule says the media should be at a given moment, the `offset_ms` of the event `timeline::lookup` finds.
- **Late start**: a program that starts more than `Timing::late_tolerance_ms` (500 ms) behind its live position. The tuner seeks forward to the live position once.
- **Read API**: `server::router`, served by `surfcult serve`. Fixed `GET` routes for channels, the schedule of a time range and health, as JSON. It listens on `127.0.0.1:8090` unless `SURFCULT_API_ADDR` says otherwise and reads the store through its own connection. See `docs/reference/api.md`.
- **API token**: `server::ApiToken`, the optional bearer token from `SURFCULT_API_TOKEN` or `SURFCULT_API_TOKEN_FILE`. With one configured, a request without exactly `Authorization: Bearer <token>` gets `401`.
- **Scheduled until**: in health, when a channel's last stored event ends, `Store::schedule_end_ms`. It shows how far the channel's schedule reaches.

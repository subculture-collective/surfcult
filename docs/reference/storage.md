# Storage

`channels.toml` is the source of truth for channels. SQLite holds what the program derives from it and what happens at run time. The code is in `src/store/` and the schema is in `migrations/`.

The `events` table holds each channel's generated schedule, one row per `timeline::Event`. Rows are keyed by channel number and start time, which is also the index for reading a time range; events of one channel must not overlap. A sequential channel continues after its last stored program event, so there is no separate cursor table; migration 0003 dropped the old `cursors` table. `playback_history` gets one row each time the tuner starts something, with a short outcome word such as `played` or `failed`. All times are Unix epoch milliseconds. `Store` opens the file in WAL mode with a 5 second busy timeout and foreign keys on, and it refuses to write an event that does not end after it starts.

The `library_items`, `library_chapters`, `library_streams`, `library_collections` and `library_collection_members` tables (migration 0002) hold a copy of the Jellyfin library: items with runtime, path and sync time, their chapters and video and audio streams, and collections with their members, each in the order Jellyfin returned them. `Store::replace_library` deletes all of it and writes the new copy in one transaction, so a reader sees the old library or the new one and a failed write changes nothing. `Store` implements `MediaSource` over these tables, so the rest of surfcult reads the library from the store. See [Jellyfin source](jellyfin.md).

Migrations are numbered SQL files (`migrations/0001_schedule.sql`) compiled into the binary and listed in `src/store/migrate.rs`. On open, each migration the database has not seen runs once, in order, in its own transaction, and is recorded in `schema_migrations`. To change the schema, add the next numbered file and list it; never edit one that has shipped. A database written by a newer build is refused rather than opened. Migration 0003 (`0003_drop_cursors.sql`) drops the `cursors` table that 0001 created.
